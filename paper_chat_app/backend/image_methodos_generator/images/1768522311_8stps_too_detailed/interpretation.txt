Here is a detailed step-by-step interpretation of the ProTeGi methodology, designed for clarity and visualization.

***

Step 1: **Initialize the beam with the initial prompt**  
Start with a single initial prompt p₀ (a human-written description of desired LLM behavior, optionally including few-shot examples). Set this as the initial beam B₀ = {p₀}, defining key parameters: beam width b (e.g., 4), search depth r (e.g., 6 iterations), minibatch size |D_mini| (e.g., 64 from training data D_tr), and metric function m (e.g., F1 score on classification tasks). This beam serves as the starting point for iterative expansion and selection.

Step 2: **Sample minibatch and identify errors (feeds into gradient generation)**  
For each prompt p in the current beam B_{i-1}, sample a minibatch D_mini ⊂ D_tr. Run the LLM (e.g., GPT-3.5-turbo at temperature 0.0) with prompt p on D_mini to collect predictions, then identify errors e (datapoints where prediction ŷ ≠ true label). Group errors into small sets (e.g., 4 errors per group); these error groups provide concrete failure cases that flow directly into the next gradient-generating prompt.

Step 3: **Generate textual gradients g using feedback prompt ∇ (guides semantic diagnosis)**  
Feed each error group e, current prompt p, and task context into the fixed gradient prompt ∇ (task-agnostic template from Appendix: "I'm trying to write a zero-shot classifier... give {num_feedbacks} reasons why the prompt could have gotten these examples wrong", e.g., num_feedbacks=4). The LLM outputs natural language "gradients" g—summaries of p's flaws (e.g., "prompt assumes hate speech always contains explicit language"). Each g acts as a semantic loss signal, mimicking gradient descent direction; multiple g's per error group enable diverse feedback.

Step 4: **Edit prompts using incorporation prompt δ to create stepped candidates p′ (applies fixes directionally)**  
For each gradient g, input p, error string, and g into the fixed editing prompt δ (Appendix template: "Based on the above information, I wrote {steps_per_gradient} different improved prompts", e.g., steps_per_gradient=4). The LLM generates successor prompts p′ by editing p in the *opposite semantic direction* of g (e.g., adding nuance for indirect hate speech). This produces targeted, interpretable improvements (e.g., 4 p′ per g), forming the core expansion; connects back to errors for recursive refinement like Socratic dialogue.

Step 5: **Expand candidates via Monte Carlo paraphrasing with LLM_mc (explores local semantic space)**  
Run each new p′ through a paraphrasing prompt (from Zhou et al., 2022: "Generate a variation... while keeping the semantic meaning") using LLM_mc at temperature 1.0, producing p″ paraphrases (e.g., p=2 per p′). This adds directionless local search around improved candidates, yielding a pool C of ~8 sampled successors per parent prompt (to cap computation); aggregates all p′ and p″ for robust neighborhood exploration before selection.

Step 6: **Perform bandit-based selection to prune to beam width b (efficiently identifies top candidates)**  
Treat |C| prompts as "arms" in best-arm-identification (e.g., UCB or Successive Rejects algorithms from Section 2.2). Within query budget B (e.g., T steps, |D_sample|=n_k per phase), iteratively sample/evaluate subsets of C on random D_sample ⊂ D_tr using metric m, balancing exploration (via UCB bonus c=2.0 or phase-wise rejects) and exploitation. Output B_i = top b prompts (e.g., via argmax weights or survivors); this minimizes expensive full evaluations, flowing top prompts to the next iteration's expansion.

Step 7: **Iterate beam search for r steps (accumulates incremental directed improvements)**  
Repeat Steps 2-6 for i=1 to r-1, evolving beam B_{i-1} → B_i. Each iteration builds on prior gradients/selections, enabling multi-step refinement (e.g., peaks at ~3 steps per learning curves); prevents overfitting via fresh minibatches and beam diversity.

Step 8: **Finalize optimal prompt from final beam (aggregates search for deployment)**  
After r iterations, evaluate all prompts in B_r on held-out test data D_te using m (e.g., maxpool F1). Select p* = argmax_{p∈B_r} m(p, D_te). This yields the optimized prompt, outperforming baselines by directing search semantically while controlling API costs (e.g., via sampling and bandits).
