### **Methodology Breakdown: Prompt Optimization with Textual Gradients (ProTeGi)**

This methodology introduces an automated process to refine and improve an initial LLM prompt. It mimics the principles of gradient descent and beam search, but instead of adjusting numerical parameters, it iteratively edits the natural language text of the prompt itself.

**Step 1: Initialization with a Starting Prompt**
The process begins with an initial, human-written prompt (`p₀`) and a small training dataset. This initial prompt is placed onto a "beam," which is a list that will hold the best `b` candidate prompts at each stage of the optimization (in the experiment, beam size `b=4`).

**Step 2: Generating Textual "Gradients"**
For each prompt on the beam, the algorithm evaluates it on a random minibatch of training data to identify errors. These errors are fed into a specific LLM prompt, called `∇` (nabla), which instructs an LLM to generate a natural language summary of the prompt's flaws—this summary is the textual "gradient" (`g`).

**Step 3: Editing Prompts via "Gradient Descent"**
The textual gradient (`g`) and the current prompt are then fed into a second LLM prompt, called `δ` (delta). This `δ` prompt instructs the LLM to perform an edit in the "opposite semantic direction" of the gradient, effectively fixing the identified flaws and generating one or more improved prompt candidates.

**Step 4: Expanding the Search Space**
This step, called the Expansion Step, combines the previous two steps and adds a final variation.
*   First, the textual gradient generation (Step 2) and editing (Step 3) are performed to create new, improved prompts.
*   Then, to further explore the semantic area, these new prompts are paraphrased using another LLM call to create additional, semantically similar candidates (Monte Carlo sampling).

**Step 5: Efficiently Selecting the Best Candidates**
Evaluating all newly generated prompts is computationally expensive, so the algorithm treats this as a "best arm identification" problem from bandit optimization. It uses an efficient algorithm like Successive Rejects or UCB Bandits to intelligently sample the performance of each candidate on a few data points, allowing it to identify the `b` most promising prompts with a minimal number of LLM API calls.

**Step 6: Iterating and Updating the Beam**
The `b` best-performing prompts selected in the previous step become the new beam for the next iteration. The entire process from Step 2 to Step 5 is repeated for a fixed number of optimization steps (e.g., 6 times in the paper's experiment), allowing the prompts on the beam to be progressively refined.

**Step 7: Final Prompt Selection**
After the final optimization step, the algorithm evaluates all prompts remaining on the final beam. The single prompt that achieves the highest score on the chosen metric (F1 score in this case) is selected as the final, optimized output (`p*`).
