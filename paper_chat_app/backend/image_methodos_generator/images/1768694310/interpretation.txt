### The ProTeGi Methodology: A Step-by-Step Breakdown

This methodology outlines an automated process for refining an initial LLM prompt to improve its performance on a specific task. The core innovation is a novel way to mimic gradient descent using natural language, where text descriptions of a prompt's flaws (textual "gradients") guide the optimization process within an efficient search algorithm.

***

**Step 1: Initialization**

The process begins by defining the starting point and goals for the optimization. A human expert provides an initial, imperfect prompt, which is placed into a "beam" (a list of top candidates) that will be refined over subsequent steps.

*   **Input:** A manually written initial prompt (`p0`), a training dataset (e.g., 50 examples for development), and a target performance metric (F1 score).
*   **Key Detail:** The initial beam (`B0`) contains only this single prompt (`p0`), and the algorithm is configured to run for a set number of iterations (e.g., 6 optimization steps) with a fixed beam width (e.g., keeping the top 4 candidates).
*   **Output:** The initial beam `B0` ready for the first optimization loop.

**Step 2: Iterative Prompt Optimization Loop**

This is the core iterative engine of the methodology, where the prompt(s) on the beam are systematically improved. The loop consists of two main phases: **Expansion**, where new and potentially better prompt candidates are generated, and **Selection**, where the most promising candidates are identified to carry forward. This entire step is repeated for the specified number of optimization steps (e.g., 6 times).

*   **Input:** The current beam of `b` promising prompts (starting with `B0`).
*   **Output:** A new, improved beam of `b` prompts for the next iteration.

    *   **Substep 2.1: Expansion - Generating Textual "Gradients"**
        First, the algorithm identifies the prompt's weaknesses. It runs the current prompt on a random minibatch of data (e.g., 64 examples), collects the errors, and feeds them into a specialized LLM prompt (`∇`) to generate natural language descriptions of why the prompt failed.
        *   **Input:** A prompt from the current beam and a minibatch of data with corresponding errors.
        *   **Output:** A set of natural language "gradients" (`g`), which are text sentences describing the prompt's flaws (e.g., "The prompt assumes that hate speech always contains explicit and direct language...").

    *   **Substep 2.2: Expansion - Editing Prompts with Gradients**
        Next, the algorithm uses the generated textual "gradients" to fix the prompt. A second specialized LLM prompt (`δ`) takes the original prompt and a gradient as input and is instructed to edit the prompt to resolve the described flaw.
        *   **Input:** The original prompt and one of its corresponding textual gradients (`g`).
        *   **Output:** A new, edited prompt candidate (`p'`) designed to be an improvement over the original.

    *   **Substep 2.3: Expansion - Monte Carlo Paraphrasing**
        To explore slight variations and increase the diversity of good candidates, the algorithm generates paraphrases of the newly edited prompts. This is done by feeding the edited prompt (`p'`) into an LLM with a simple instruction to rephrase it while preserving the semantic meaning.
        *   **Input:** An edited prompt candidate (`p'`).
        *   **Output:** A small number of additional, semantically similar prompt candidates (`p''`) (e.g., 2 per edited prompt).

    *   **Substep 2.4: Selection - Efficient Candidate Evaluation**
        With a large pool of new candidates from the expansion steps, the algorithm must efficiently find the best ones without exhaustively testing each one. It treats this as a "best arm identification" problem, using bandit algorithms (like UCB or Successive Rejects) to intelligently allocate a limited evaluation budget, quickly identifying the top `b` (e.g., 4) candidates based on their estimated F1 score on small data samples.
        *   **Input:** The full set of new prompt candidates generated in substeps 2.2 and 2.3.
        *   **Output:** The `b` highest-performing prompts, which form the new beam for the next iteration of the loop.

**Step 3: Final Prompt Selection**

After the optimization loop has completed all its iterations, the algorithm performs a final selection. The prompts remaining on the final beam represent the best candidates found throughout the entire search process.

*   **Input:** The final beam of `b` prompts from the last optimization iteration.
*   **Process:** The performance of each prompt on the final beam is evaluated to determine the single best one.
*   **Output:** The single, optimized prompt that achieved the highest score on the target metric (F1 score).
