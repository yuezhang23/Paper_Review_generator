### **OPRO (Optimization by PROmpting) Methodology: A Step-by-Step Interpretation**

This methodology uses a Large Language Model (LLM), designated as the "optimizer," to iteratively generate and refine solutions for a given problem. The performance of these solutions is evaluated by another LLM, the "scorer," on a training dataset. The core of the process is a loop where the optimizer learns from a history of previously generated solutions and their scores to propose increasingly better ones.

---

**Step 1: Problem Setup and Dataset Preparation**
First, the optimization task is defined, and the necessary models and data are prepared. This involves selecting an optimizer LLM to generate solutions and a scorer LLM to evaluate them, then splitting a relevant dataset into training and testing sets.
- **Input**: A task (e.g., prompt optimization for math reasoning), a public dataset (e.g., GSM8K), and a selection of LLMs (e.g., PaLM 2-L, text-bison, GPT-4).
- **Output**: A small training subset to efficiently calculate scores during optimization (e.g., 3.5% of the GSM8K training set) and a full, held-out test set for final validation.

**Step 2: Generate Initial Solution Trajectory**
The process is kickstarted with a small set of initial solutions to create the first "optimization trajectory." These starting points can be simple, generic prompts (e.g., "Let's solve the problem." or an empty string) or randomly generated solutions for mathematical problems.
- **Input**: The task definition.
- **Output**: An initial set of solution-score pairs, created by evaluating the starting solutions on the training subset.

**Step 3: Construct the Meta-Prompt**
A comprehensive "meta-prompt" is constructed to guide the optimizer LLM in the main loop. This prompt assembles the entire context of the optimization problem into a single input.
- **Input**: The current optimization trajectory from the previous step (or the initial one from Step 2).
- **Output**: A formatted meta-prompt containing three key components:
    1.  **Optimization Trajectory**: The top 20 best-performing solution-score pairs found so far, sorted in ascending order of their scores.
    2.  **Problem Description**: A few (e.g., 3) randomly sampled examples from the training set to show the optimizer what the task looks like.
    3.  **Meta-Instructions**: Direct commands to the optimizer, explaining its goal (e.g., "generate a new instruction that achieves a higher accuracy").

**Step 4: Iterative Optimization Loop**
This is the core iterative engine of OPRO, where the optimizer LLM generates new solutions, which are then evaluated and used to inform the next cycle. This loop continues until a stopping condition is met, such as reaching a maximum number of steps (e.g., 200) or failing to find better solutions.

-   **Substep 4.1: Generate New Candidate Solutions**
    The optimizer LLM is prompted with the meta-prompt from Step 3 to generate a batch of new, diverse solutions.
    -   **Input**: The complete meta-prompt.
    -   **Output**: A batch of new candidate solutions (typically 8), generated with a high temperature (e.g., 1.0) to encourage creativity and exploration.

-   **Substep 4.2: Evaluate New Solutions**
    Each new candidate solution is evaluated by the scorer LLM on the training subset to determine its effectiveness.
    -   **Input**: The batch of new solutions and the training subset.
    -   **Output**: A corresponding score (e.g., training accuracy) for each new solution.

-   **Substep 4.3: Update the Optimization Trajectory**
    The newly generated solution-score pairs are added to the existing history, and the list is pruned to maintain a fixed size.
    -   **Input**: The previous trajectory and the new solution-score pairs.
    -   **Output**: An updated optimization trajectory containing only the top 20 solutions, which feeds back into **Step 3** to construct the meta-prompt for the next iteration.

**Step 5: Select the Optimal Solution**
Once the iterative loop terminates, the single best-performing solution is identified from the final, complete history of generated solutions.
- **Input**: The final optimization trajectory containing all evaluated solutions and their scores.
- **Output**: The single solution with the highest score achieved during the entire optimization process.

**Step 6: Final Validation on Test Set**
The optimal solution selected in Step 5 is rigorously evaluated on the unseen test set to measure its true performance and generalization ability.
- **Input**: The optimal solution and the full, held-out test set.
- **Output**: A final test accuracy or performance score, calculated using the scorer LLM with a temperature of 0 for deterministic, greedy decoding. This result validates whether the optimization on the training data successfully transferred to new data.
